1. **下载**  
   从 [Releases](https://github.com/huangdihd/MovementSync/releases) 获取最新版本：

## World 世界数据接口

其他插件可通过 `MovementSync.INSTANCE.getWorld()` 读取服务端下发的当前世界缓存。除名称中明确写着
`chunk` 的参数外，下列接口均使用方块坐标。返回的快照可安全保留；`Optional`／`OptionalInt.empty()`
表示区块或该项数据尚未知，并不表示数值为零。

- 光照：`getSkyLight(x, y, z)` 与 `getBlockLight(x, y, z)` 返回 0～15；MovementSync 只保存服务端更新，不在客户端重算光照传播。
- 方块实体：`getBlockEntityAt(x, y, z)` 与 `getBlockEntitiesInChunk(chunkX, chunkZ)` 返回不可变 `BlockEntitySnapshot`，包含类型及服务端 NBT；服务端省略 NBT 时 `nbt()` 为 `null`。
- 高度图：`getHeight(type, x, z)` 返回 `HeightmapTypes` 指定列的绝对世界 Y。
- 生物群系：`getBiomeId(x, y, z)` 返回网络 ID；`getBiomeName(x, y, z)` 使用最新生物群系注册表解析名称。
- 服务端区块设置：`getChunkCacheCenter()`、`getChunkCacheRadius()`、`getSimulationDistance()` 返回最近收到的值。
- 默认出生点：`getDefaultSpawn()` 返回最近收到的 `DefaultSpawn` 位置及朝向。
- `loadedChunks()` 仍返回已加载区块坐标的不可变快照；需要多个读取保持同一时刻的一致性时，可用 `readTerrain(...)` 将它们放在同一个读锁中。

区块卸载、切换维度、断线及 `World.clear()` 都会清除对应缓存。

## 有屋顶维度的飞行

静态 goto 在观测到的岩浆附近使用已知落点回程余量，不要求整个对岸预先加载。资源估算复用 `GlideRange` 的烟花调度，包含库存顺序、冷却、确认延迟和保守推力寿命。`ReserveMonitor` 在后台约每十个物理 tick 及相关事件刷新；新加载的有支撑落点可更新已知落点。起飞预算保留一个向外飞行的烟花复用窗口及回程资源。计划内折返用共享物理预演完整掉头、爬升、回程和支撑触地，再按物理／资源检查点执行控制序列，不做每 tick 每候选终局证明。回岸完成后终止原 goto，不再向不可达对岸步行寻路；日志以 `Planned return` 区分折返和到达。末地及 follow 保持原策略。64 枚跨海、3 枚起飞前拒绝及无对岸实际返岸的合成物理回归已通过；这不是通用安全保证，也未实机验证，尤其不保证外部修正、地形变化或附件时序偏离后的行为。

实机反馈修正：返航发布滞后 1～8 tick 时，只有库存未变且没有附着烟花，才可从当前状态重放整段既定控制序列并重新验证后接纳；检查点偏离仍使计划失效。返航失效后保留局部控制，执行地形检查后的动力脱险，不再无动力等待。岩浆上方巡航请求八格高度余量，暴露状态下速度低于 0.8 格/tick 时补充动力；有支撑岸边到达不会仅因附近有岩浆而持续加速。起飞预算的水平前飞被地形阻挡时，可尝试有界爬升轨迹。这些是有界策略，不保证任意屋顶、冷却或附件延迟下都能脱险。上一版 Windows 下界／Grim 实机失败；本次修正有合成回归覆盖，仍待实机复验。

第二轮实机复查：周期监测调用 `KnownLandingReserve.assess`，使用可扩展的烟花调度估算，不做精确触地预演。显式诊断 `ReserveMonitor.resolveReturnEstimate` 则报告获准精确轨迹实际消耗的烟花数；这一契约与保守回程余量估算分开。附近可行落点独立于远处落点评估，`UNKNOWN` 不作为资源不足。目标有效性按寻路的精确脚部坐标站立判定检查，不使用要求宽5×5支撑、会向下搜索的滑翔落点判据；窄台和台阶上可站立的目标不会因此被拒绝。确认目标不可站立时明确报告拒绝，但不在空中放弃操纵：局部安全控制及余量监测持续到落地或资源触发返航，目标几何本身不触发返航。真实位置数据包路径上的远距离修正清除落点记忆，并使飞行控制 epoch、移动局部状态和返航计划失效；小幅修正保留落点记忆，切换维度及死亡则清除记忆。诊断记录具体触发条件、观测／当前资源、回程需求和继续飞行余量；实际 `trajectoryTicks` 与累计搜索工作量 `simulatedSteps` 分开。起飞拒绝诊断区分前飞受阻、无落点、回程未证明、库存余量不足及无效资源。第五轮反馈还修正了落地制动、危险出口及非滑翔交接的 yaw 写入，复用既有最近等价角工具。发包路径回归约束相邻 yaw 差值不超过180°，并保持物理／use-item 朝向一致；这修复了可复现的整圈跳变，但日志不足以唯一确定 AimModulo360 的实机原因。仍需 Windows 下界／Grim 复验；此前单次跟随 Simulation 告警仍未查明。编译／验收使用 `mvn -o -Dmaven.compiler.release=17 test`（及 `package`），不使用仅 Java 21 提供的 API。

### P5f 后续修正（进行中，尚未验收）

第七轮 Windows 下界／Grim 实机反馈：使用此前报告通过990项测试的 jar，约180格、目标为 `(175, 60, -32)` 的 goto 出现严重回归。机器人日志记录16次水平碰撞，俯仰均为 -20，飞行高度曾达到约 Y96～115，最终 `death.attack.flyIntoWall`；其中13条碰撞记录附着烟花，并非全部16条。用户另报告两次 Simulation 告警并中止测试；机器人日志中未找到对应告警字符串。因此，第六轮短程 goto／follow 成功不能作为验收依据。稀疏运动采样或旧版 `lastDecision`／预测字段为空均不能确定实际控制所有者；实机原因尚不能唯一归因，现有地形／所有权记录不足以精确重放事故。

- **高空有支撑目标进近：**静态目标已加载、安全且有支撑，位于机器人下方、水平距离小于32格时，局部 goto 将高度超调视为进近／下降，而非下一段巡航；使用已有的经过检查的落地候选，不再额外请求巡航加速。低于目标时的爬升需求、无支撑目标、follow 与实际触地检查仍按各自策略处理；这不意味着允许在任意地形落地。
- **有界缺失控制兜底：**有效获准控制及 movement 自有的独立落地控制优先。紧急接管要求已知危险表面（或已加载的虚空边界）在垂直12格范围内，且水平低速（低于0.8格／tick）或正在下沉，但不覆盖已确认的有动力上升。远处岩浆和累计 `fallDistance` 本身不再赋予硬兜底爬升权限。当前每段空中飞行最多允许24个姿态干预 tick 和一次烟花请求；所有者／epoch 变化或位置纠正不会补充预算。仍须通过已加载地形碰撞／伤害扫掠、库存、请求冷却及附着状态检查。INFO 接管／释放日志包含原因、位置、危险高度和所有者。这是有界干预，不是脱险或落地保证。
- **天花板与接纳审查：**局部进近重放及兜底扫掠会从同一个有动力状态额外计算无推力 travel 步，避免移动后施加的烟花推力掩盖撞顶后的垂直速度归零。有动力前缀接纳和重新验证也检查施加推力之前的撞顶接触。已注册的旧版紧急转向现在也须通过扫掠检查。经检查的安全触地延续可保留合法下降，而非强制无关爬升；危险下降检查并未移除。
- **岩浆巡航与返航：**岩浆上方八格余量仍是响应式目标，不是轨迹不变量，也不保证屋顶或推力不可用时存活。已有附着推力可使用经过检查的脱险转向而不重复请求烟花。返航保留提前物理拉起及既有轨迹的累计下落／安全支撑触地检查；返航审计不证明本次实机事故由返航控制导致。不放宽物理、资源记账或落地标准。

P5f 自动化验收：连续两次 `mvn -o -Dmaven.compiler.release=17 test` 及随后 `package` 均通过，每轮1055次测试执行、零失败／错误、1项跳过；数量含继承测试的重复执行，并非1055个独立场景。首次集成暴露了 follow 回归，将新增下降检查限定于降落后，原 follow 测试在断言不变的情况下恢复通过；既有180／600物理回归也通过。这些合成结果不能唯一解释历史实机事故，也不构成实机修复确认；仍待 Windows 下界／Grim 复验。

维度注册表的 `has_ceiling` 决定是否应用屋顶策略；`min_y` / `height` 是世界边界，`logical_height` 不是屋顶高度。屋顶面由已加载列的实际最高碰撞面确定，不写死基岩高度。

- 已在屋顶上时沿用地形上方巡航；静态目标上方有屋顶碰撞时，在目标水平位置附近选择安全屋顶落点。落地后提示“目标在屋顶下,无法到达”，结束 goto 并清除恢复目标。
- 屋顶下 goto 异步检查已加载地形中的几何通道，以及共享物理的跳跃／展开预演；目标区块未加载不直接否决分段航线。地面部署被拒后，可先进行一次有界内陆起飞点搜索：采样周围 8～16 格有支撑位置，最多 16 次步行寻路、四种起飞朝向。候选必须通过同一套严格中断／metadata 延迟双轨迹检查及适用的航线／资源准入（观测到岩浆附近使用已知回程余量）；走到后停稳并重新验证才起飞，无可用结果仍退回走路。其他准备失败记录装备／预算、展开预演、通道搜索或 worker 状态等原因；不自动上屋顶、下钻或搭方块。危险下落仍使用共享物理救援检查。
- 静态 goto 的飞行结束不等于到达：普通落地后继续走向原始三维目标，完成计划内余量折返则终止原请求。走到部分路径末尾后续算；暂时无续接路径时保留目标、每 20 执行 tick 重试。200 执行 tick 没有完成新节点仍会如实报失败并清除恢复意图，重规划不重置该看门狗。失败不再记录为 `arrived`。
- 跟随非滑翔实体使用按跟随距离后退的空中路点，在地面终点上方保留身体和预演下沉所需净空，不使用地形顶部巡航高度。到达路点或进入跟随距离不结束追飞；只有目标贴地且减速至走路能追上时，才选择目标附近有支撑的落点，从机器人实际状态规划通道内落地。普通服务器位置修正保留活动跟随意图，不再隐式变成停止并落地；飞行子任务失败仍保留落地控制，触地后恢复走路跟随。目标滑翔时保留原追法。迫降复用普通落点搜索，并增加完整通道可达性验证。开放维度及屋顶之上的固定目标保留原巡航策略。
- 有界三维 A* 只搜索位置，排除未知、碰撞及伤害空间，以视线检查平滑几何路点。远距离或尚未完全加载的目标返回分段航线，由 worker 滚动重规划，不再设置 128 格目标截断。执行时从实际状态重新枚举 yaw／pitch／烟花，用共享滑翔物理和实时通道净空检查打分，不重放逐 tick 操纵；追飞评分累计预演跟踪误差及包含爬升的速度误差，但中间几何路点保持静止。落在实体地形内部的追飞终点向上寻找已加载净空，避免目标穿过山脊时所有规划立即失效。搜索预算和物理推导余量见规划器注释；有界搜索仍是保守方案，不保证找到所有可行航线。
- 追飞在起伏地面及树木碰撞形状上方仍保留物理推导的下沉余量，并按烟花预演可达距离检查终点前方。通道控制暂时不可用时，先预演带／不带烟花的局部持续滑翔操纵，确无安全空中候选才退回无伤优先迫降；“触地无伤”本身不算有效追飞。地面目标丢失后转为前往最后位置的行程，保留起飞预演及固定终点走路回退，不再因上次飞行失败立即结束跟随。空中最后位置则解析到已知有支撑落点，落地后结束搜索，不再对同一个空中坐标反复起飞。落地承诺使用目标速度滤波的剩余位移预演和固定落地锚点，只有预演离开保持距离范围（含身体余量）才恢复追赶；所有追飞回退都检查实际轨迹，不凭阶段名称放行触地。通道选择抛出失败时，也先重新验证局部追飞再尝试终局恢复；无伤地形返回的“无需恢复、没有操纵”不代表不能继续追飞。诊断区分恢复预算耗尽与几何／操纵拒绝。低空路线选择先用独立有界预算重放此前成功的恢复操纵，重新检查当前地形、库存与冷却，不缓存安全结论。goto 和跟随共用朝前方路线段的回接尝试，再考虑终局／应急操纵。通道诊断记录投影点、方向和观测／证明 tick 标识，不再报告未对齐时间的单步误差。低空原版操纵现在携带起点物理 tick 与导航所有权，在输入边界重放复验（最多接纳八 tick 前的计算），所选操纵期限为六 tick，之后接独立准备的有限着地续接。昂贵准备在物理监视器外，消费时最多重放六步。这不是通用安全保证：偏移后接纳没有重新证明完整终局轨迹，多烟花恢复与插件操纵路径尚未覆盖，全部已准备续接失效时仍使用明确未证明安全的下降操纵。单纯几何验证仍不够。模式选择同时参考最近观测速度和滤波速度，避免滤波初期误判需要落地；落点超出目标的跟随范围时不提交跟随落地。
- 规划等待期间清除旧移动和跳跃输入，地面保持蹲伏；拒绝起点已偏移的低空计划。低空及危险岸边起飞检查不展开、展开后前五 tick 中断的安全支撑分支。危险岸边另检查有界触地／停稳预演：服务端改用走路物理，客户端滑翔 metadata 延迟 1、2、4 tick，两条轨迹均须保持安全支撑并最终停稳，但不要求位置相等。客户端在权威 metadata 到达前保留滑翔标志，不提前清标志，也不假定 Grim 容差。这是保守拒飞门槛，不是任意后续操纵或网络延迟的完整证明。低空 goto 在起跳前准备已加载的（可分段）航线；同一 travel 请求不重复尝试已拒绝的起飞。普通走路验证下一步后松键滑行（最多 80 tick），危险边缘跳跃也检查该分支。失败分支继续模拟触地后的余速直至停稳，首个展开 tick 使用站立身体高度。危险岸边交接保留蹲伏，仍处于滑翔物理时先验证反向刹车；已经越过可刹停边界的状态只报告未证明，不保证救援。不覆盖后续外力或地形变化。普通执行边连续八个执行间隔没有可测三维位移时也会拒绝该边（不计挖掘／放置子任务等待），日志记录当前输入及预演阻挡原因，不再只等全局看门狗。被安全检查拒绝的路径边会在当前请求中排除，使用完整但有节点预算的搜索重规划；无可执行续路报 UNSAFE_ROUTE，日志区分预算耗尽、未加载边界和搜索耗尽，并记录排除边与展开节点数。走路也排除身体碰到的 fire/soul_fire 等伤害格。失败/取消清除旧输入并按当前状态独立接管安全落地或有限地面脱险，非滑翔空中状态也预演触地和余速风险，独立落地在 metadata 清除滑翔后继续接管；重复取消不丢弃已有安全控制器。服务端修正与 metadata 日志记录前后状态，取消原因区分位置修正和显式停止。地面脱险须证明离开伤害区后不再进入且能在安全支撑上停稳；无证明则告警，不承诺从封闭火场/大岩浆池获救，也不模拟灭火或剩余生命。低空执行拒绝水平碰撞和脱离通道的候选；救援在资源允许时尝试已证明的更靠近目标的落点，失败保留原安全方案。终点低空接近阶段增加反向刹车候选并停止新烟花，烟花执行层也检查冷却；日志区分库存与冷却后的当前可用数。起飞生命周期写入 INFO；无进展 WARN 同行附带节点、速度、着地和周边支撑。
- 实时滑翔与飞行预演共用原版 float 身体尺寸：半宽 `0.6F / 2`、高度 `0.6F`（再提升为 double），支撑及伤害空间查询也使用相同尺寸；不再使用 `.299` 的滑翔碰撞内缩。
- 低空通道在伤害格上方按剩余烟花、冷却和附着状态证明可达安全支撑面，水平速度归零的分支也允许使用实际剩余烟花，不再要求无动力跨海。复用末地的 `GlideRange` 最短火箭寿命、`LandingSearch` 已加载落点与 `LandingMemory`；范围估计不能替代屋顶下逐 tick 碰撞／伤害验证。候选耗用烟花后仍须保留恢复能力；无法证明时保守拒绝，已进入不可恢复状态则不保证救援成功。恢复证明先排序候选并复用控制搜索提示（每次仍重新验证到终局，不缓存安全结论）；每次选择器调用或六步安全验证最多使用 24,000 次恢复物理步，落点搜索最多访问 512 个节点。此预算不是整个运动 tick 的统一上限；完整恢复证明目前仍同步执行，尚未实现带地形版本及完整控制序列的 worker 安全交接。
- 灵魂沙／灵魂土边界的走路速度乘数按原版脚下支撑方块的 X/Z 查询，不再仅取脚中心下方。支撑选择使用脚下薄片、最近方块中心及原版平局次序，保留灵魂沙 14/16 碰撞高度与灵魂土不减速语义。
- 死亡及复活清除飞行状态、旧动作和滑翔元数据；只有新展开请求成功发出后才重新接受滑翔标志，避免旧生命的元数据触发安全落地。重新登录仍允许正常接管空中重连状态。
- 所有维度的标准飞法规则拒绝穿过岩浆、火及灵魂火的轨迹；落地排除热伤害支撑（包括岩浆块、点燃的营火）及站立身体附近的岩浆。使用保守整格接触检查，不模拟持续燃烧和伤害冷却。
