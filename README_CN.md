## 快速开始

1. **下载**  
   从 [Releases](https://github.com/huangdihd/MovementSync/releases) 获取最新版本：  
   `MovementSync-[version].jar`

2. **复制** 到你的插件目录。

3. **启动** [xinbot](https://github.com/huangdihd/xinbot)。

## 命令

| 命令 | 描述 |
|-----------|-------------|
| `whereami` | 显示当前位置和旋转 |
| `jump` | 执行一次跳跃 |
| `getblockat` | 获取指定坐标的方块信息 |
| `walk` | 向指定方向行走一段时间 |
| `lookat` | 看向指定坐标 |
| `movement` | 控制运动控制器 (暂停/恢复/取消) |
| `entities` | 列出世界中的实体 |
| `interactblock` | 与方块交互 |
| `interactentity` | 与实体交互 |
| `inventory` | 显示背包信息 |
| `container` | 显示当前容器内容 |
| `ispassable` | 检查方块是否可通行 |
| `lookatentity` | 通过 ID 看向实体 |
| `goto` | 寻路至指定坐标;目标较远且有鞘翅和烟花时会自动飞过去(`goto <x> <y> <z> walk` 强制步行) |
| `elytra` | 鞘翅飞行:`start`、`boost`、`status`、`fly <x> <z> [y]` |
| `follow` | 通过 ID 跟随实体 |
| `ride` | 骑乘实体或下车 |
| `cansee` | 检查从机器人到头部的视线是否可见某点 |
| `stopmove` | 停止所有运动并清除目标 |
| `debug` | 打印当前调试状态 |
| `debug localgoto on\|off` | 低空复杂 goto 局部控制器开关，默认 on；off 回到旧控制器，不影响 follow／末地／高空 |
| `debug shadow on\|off` | 开关飞行诊断；旧控制路径输出影子对比，新局部路径输出前缀及拒绝分类 |

## 有屋顶维度的飞行

维度注册表的 `has_ceiling` 决定是否应用屋顶策略；`min_y` / `height` 是世界边界，`logical_height` 不是屋顶高度。屋顶面由已加载列的实际最高碰撞面确定，不写死基岩高度。

- 已在屋顶上时沿用地形上方巡航；静态目标上方有屋顶碰撞时，在目标水平位置附近选择安全屋顶落点。落地后提示“目标在屋顶下,无法到达”，结束 goto 并清除恢复目标。
- 屋顶下 goto 异步检查已加载地形中的几何通道，以及共享物理的跳跃／展开预演；目标区块未加载不直接否决分段航线。准备失败退回走路，并记录装备／预算、展开预演、通道搜索或 worker 状态等原因；不自动上屋顶、下钻或搭方块。危险下落仍使用共享物理救援检查。
- 静态 goto 的飞行结束不等于到达：落地后继续走向原始三维目标。走到部分路径末尾后续算；暂时无续接路径时保留目标、每 20 执行 tick 重试。200 执行 tick 没有完成新节点仍会如实报失败并清除恢复意图，重规划不重置该看门狗。失败不再记录为 `arrived`。
- 跟随非滑翔实体使用按跟随距离后退的空中路点，在地面终点上方保留身体和预演下沉所需净空，不使用地形顶部巡航高度。到达路点或进入跟随距离不结束追飞；只有目标贴地且减速至走路能追上时，才选择目标附近有支撑的落点，从机器人实际状态规划通道内落地。普通服务器位置修正保留活动跟随意图，不再隐式变成停止并落地；飞行子任务失败仍保留落地控制，触地后恢复走路跟随。目标滑翔时保留原追法。迫降复用普通落点搜索，并增加完整通道可达性验证。开放维度及屋顶之上的固定目标保留原巡航策略。
- 有界三维 A* 只搜索位置，排除未知、碰撞及伤害空间，以视线检查平滑几何路点。远距离或尚未完全加载的目标返回分段航线，由 worker 滚动重规划，不再设置 128 格目标截断。执行时从实际状态重新枚举 yaw／pitch／烟花，用共享滑翔物理和实时通道净空检查打分，不重放逐 tick 操纵；追飞评分累计预演跟踪误差及包含爬升的速度误差，但中间几何路点保持静止。落在实体地形内部的追飞终点向上寻找已加载净空，避免目标穿过山脊时所有规划立即失效。搜索预算和物理推导余量见规划器注释；有界搜索仍是保守方案，不保证找到所有可行航线。
- 追飞在起伏地面及树木碰撞形状上方仍保留物理推导的下沉余量，并按烟花预演可达距离检查终点前方。通道控制暂时不可用时，先预演带／不带烟花的局部持续滑翔操纵，确无安全空中候选才退回无伤优先迫降；“触地无伤”本身不算有效追飞。地面目标丢失后转为前往最后位置的行程，保留起飞预演及固定终点走路回退，不再因上次飞行失败立即结束跟随。空中最后位置则解析到已知有支撑落点，落地后结束搜索，不再对同一个空中坐标反复起飞。落地承诺使用目标速度滤波的剩余位移预演和固定落地锚点，只有预演离开保持距离范围（含身体余量）才恢复追赶；所有追飞回退都检查实际轨迹，不凭阶段名称放行触地。通道选择抛出失败时，也先重新验证局部追飞再尝试终局恢复；无伤地形返回的“无需恢复、没有操纵”不代表不能继续追飞。诊断区分恢复预算耗尽与几何／操纵拒绝。低空路线选择先用独立有界预算重放此前成功的恢复操纵，重新检查当前地形、库存与冷却，不缓存安全结论。goto 和跟随共用朝前方路线段的回接尝试，再考虑终局／应急操纵。通道诊断记录投影点、方向和观测／证明 tick 标识，不再报告未对齐时间的单步误差。低空原版操纵现在携带起点物理 tick 与导航所有权，在输入边界重放复验（最多接纳八 tick 前的计算），所选操纵期限为六 tick，之后接独立准备的有限着地续接。昂贵准备在物理监视器外，消费时最多重放六步。这不是通用安全保证：偏移后接纳没有重新证明完整终局轨迹，多烟花恢复与插件操纵路径尚未覆盖，全部已准备续接失效时仍使用明确未证明安全的下降操纵。单纯几何验证仍不够。模式选择同时参考最近观测速度和滤波速度，避免滤波初期误判需要落地；落点超出目标的跟随范围时不提交跟随落地。
- 规划等待期间清除旧移动和跳跃输入，地面保持蹲伏；拒绝起点已偏移的低空计划。低空及危险岸边起飞检查不展开、展开后前五 tick 中断的安全支撑分支。危险岸边另检查有界触地／停稳预演：服务端改用走路物理，客户端滑翔 metadata 延迟 1、2、4 tick，两条轨迹均须保持安全支撑并最终停稳，但不要求位置相等。客户端在权威 metadata 到达前保留滑翔标志，不提前清标志，也不假定 Grim 容差。这是保守拒飞门槛，不是任意后续操纵或网络延迟的完整证明。低空 goto 在起跳前准备已加载的（可分段）航线；同一 travel 请求不重复尝试已拒绝的起飞。普通走路验证下一步后松键滑行（最多 80 tick），危险边缘跳跃也检查该分支。失败分支继续模拟触地后的余速直至停稳，首个展开 tick 使用站立身体高度。危险岸边交接保留蹲伏，仍处于滑翔物理时先验证反向刹车；已经越过可刹停边界的状态只报告未证明，不保证救援。不覆盖后续外力或地形变化。普通执行边连续八个执行间隔没有可测三维位移时也会拒绝该边（不计挖掘／放置子任务等待），日志记录当前输入及预演阻挡原因，不再只等全局看门狗。被安全检查拒绝的路径边会在当前请求中排除，使用完整但有节点预算的搜索重规划；无可执行续路报 UNSAFE_ROUTE，日志区分预算耗尽、未加载边界和搜索耗尽，并记录排除边与展开节点数。走路也排除身体碰到的 fire/soul_fire 等伤害格。失败/取消清除旧输入并按当前状态独立接管安全落地或有限地面脱险，非滑翔空中状态也预演触地和余速风险，独立落地在 metadata 清除滑翔后继续接管；重复取消不丢弃已有安全控制器。服务端修正与 metadata 日志记录前后状态，取消原因区分位置修正和显式停止。地面脱险须证明离开伤害区后不再进入且能在安全支撑上停稳；无证明则告警，不承诺从封闭火场/大岩浆池获救，也不模拟灭火或剩余生命。低空执行拒绝水平碰撞和脱离通道的候选；救援在资源允许时尝试已证明的更靠近目标的落点，失败保留原安全方案。终点低空接近阶段增加反向刹车候选并停止新烟花，烟花执行层也检查冷却；日志区分库存与冷却后的当前可用数。起飞生命周期写入 INFO；无进展 WARN 同行附带节点、速度、着地和周边支撑。
- 实时滑翔与飞行预演共用原版 float 身体尺寸：半宽 `0.6F / 2`、高度 `0.6F`（再提升为 double），支撑及伤害空间查询也使用相同尺寸；不再使用 `.299` 的滑翔碰撞内缩。
- 低空通道在伤害格上方按剩余烟花、冷却和附着状态证明可达安全支撑面，水平速度归零的分支也允许使用实际剩余烟花，不再要求无动力跨海。复用末地的 `GlideRange` 最短火箭寿命、`LandingSearch` 已加载落点与 `LandingMemory`；范围估计不能替代屋顶下逐 tick 碰撞／伤害验证。候选耗用烟花后仍须保留恢复能力；无法证明时保守拒绝，已进入不可恢复状态则不保证救援成功。恢复证明先排序候选并复用控制搜索提示（每次仍重新验证到终局，不缓存安全结论）；每次选择器调用或六步安全验证最多使用 24,000 次恢复物理步，落点搜索最多访问 512 个节点。此预算不是整个运动 tick 的统一上限；完整恢复证明目前仍同步执行，尚未实现带地形版本及完整控制序列的 worker 安全交接。
- 灵魂沙／灵魂土边界的走路速度乘数按原版脚下支撑方块的 X/Z 查询，不再仅取脚中心下方。支撑选择使用脚下薄片、最近方块中心及原版平局次序，保留灵魂沙 14/16 碰撞高度与灵魂土不减速语义。
- 死亡及复活清除飞行状态、旧动作和滑翔元数据；只有新展开请求成功发出后才重新接受滑翔标志，避免旧生命的元数据触发安全落地。重新登录仍允许正常接管空中重连状态。
- 所有维度的标准飞法规则拒绝穿过岩浆、火及灵魂火的轨迹；落地排除热伤害支撑（包括岩浆块、点燃的营火）及站立身体附近的岩浆。使用保守整格接触检查，不模拟持续燃烧和伤害冷却。
